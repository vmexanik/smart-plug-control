Shelly і Tasmota

Найпростіший шлях. У формі розетки оберіть Shelly (Gen1), Shelly (Gen2+/Gen3) або Tasmota і введіть IP-адресу. Адреси команд хаб складе сам. Або скористайтеся автопошуком, і форма заповниться сама.

  • Задайте пристрою постійну IP-адресу (резервування DHCP на роутері). Якщо IP зміниться, розетка стане «не на зв'язку» й доведеться оновити адресу в її формі.
  • Якщо на пристрої увімкнено пароль, його видно в пошуку як «(потрібен пароль)». Логін і пароль Basic-авторизації вводяться у формі розетки.
  • Для Shelly і Tasmota хаб показує споживання, якщо розетка його вимірює.

Які команди надсилає хаб

Корисно знати, якщо розетку треба перевірити вручну чи налаштувати файрвол.

ТипУвімкнути
Shelly Gen1GET /relay/0?turn=on
Shelly Gen2+GET /rpc/Switch.Set?id=0&on=true
TasmotaGET /cm?cmnd=Power1%20On
ESPHomePOST /switch/<id>/turn_on

Вимикання відрізняється останнім словом (off / false / Off / turn_off).

Лише перший канал Автоматично підставляється керування першим каналом (Shelly id=0, Tasmota Power1). Багатоканальні пристрої (подовжувачі, багатоканальні реле) в пошуку позначені як «реле», а адреси для каналів 2+ потрібно вказати вручну в режимі «HTTP».

Довільний HTTP

Підійде будь-який пристрій, який вмикається звичайним HTTP-запитом:

  • URL для увімкнення і URL для вимкнення: повні адреси, наприклад http://192.168.1.50/relay/0?turn=on.
  • Прапорець POST замість GET: для пристроїв, яким потрібен POST.
  • Логін і пароль: якщо пристрій вимагає Basic-авторизацію.
  • Поле «URL статусу» зараз зберігається, але хаб ним не користується.

Підтримується лише http://, без шифрування.

MQTT

  1. Задайте брокера Вкладка «Системні налаштування», розділ MQTT: URI (mqtt://192.168.1.10:1883), за потреби користувач і пароль, потім «Зберегти налаштування».
  2. Додайте розетку з драйвером MQTT Вкажіть топік команди (наприклад shellies/shelly1/relay/0/command) та тексти ON/OFF (on / off).
  3. Оберіть QoS і Retain Для більшості випадків QoS 0 без Retain. Retain корисний, якщо пристрій має підхопити останню команду після перепідключення до брокера.

Хаб лише публікує команди. Стан розетки він із MQTT не читає, тому в таких розеток немає опитування стану та показів потужності.

Коли розетка недоступна

Для розеток з розпізнаним типом (Shelly, Tasmota) хаб раз на 10 с перевіряє, чи вони «на зв'язку». Якщо ні:

  • на картці з'являється «(не на зв'язку)», кнопка сіріє;
  • команди одразу відхиляються, а не чекають довгого таймауту;
  • коли пристрій з'явиться знову, хаб сам перечитає його справжній стан (наприклад, якщо хтось натиснув кнопку на корпусі) і запише це в журнал.

Для довільного HTTP та MQTT такого опитування немає, тому вони вважаються доступними завжди.
